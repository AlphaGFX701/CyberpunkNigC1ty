3. ฉากสำรวจศูนย์ควบคุม 2.5D

ใช้มุมมองและขนาดคินตรงกับร้านอรุณและสถานี
ฉากต้องประกอบอย่างมีเหตุผล มีพื้น เงาสัมผัส
collision และการบังตัวละครตามตำแหน่งเท้า

พื้นที่หลัก:
- ทางเข้าและจุดตรวจเจ้าหน้าที่
- ห้องปฏิบัติการที่มีจอเครือข่ายขนาดใหญ่
- ทางเดินระหว่างตู้เซิร์ฟเวอร์
- ห้องเก็บบันทึกต้นฉบับ
- ตู้เชื่อมต่อ CONTROL-03
- ประตูนิรภัยไปยังห้อง BLACKBOX
- ห้องเผชิญหน้า NULL

ออกแบบทางเดินเป็นวงเชื่อมสองฝั่ง มีทางแยกสั้น
ไม่ให้เป็นทางตรงจากประตูไปกดเครื่องสุดท้าย

สองเบาะแสต้องอยู่กับอุปกรณ์จริง:

- ข้อมูลวิ่งบนจอและสายส่งที่กำลังใช้งาน
- ไฟหลอดหรี่และคืนแสงอย่างนุ่มนวล
- เมืองด้านนอกมีป้ายไฟและยานผ่านเป็นบางครั้ง
- ประตูนิรภัยเปิดจริงหลังปลดล็อก
- ซ่อมสำเร็จแล้วเครื่องที่เกี่ยวข้องต้องเปลี่ยนสถานะให้เห็น

ไม่ทำให้อาคารหรืออุปกรณ์ทั้งหมดลอยหรือกระเด้ง

5. เจ็ดภารกิจ HTML/CSS

อ้างอิงหัวข้อจาก W3Schools

ด่าน 1 — คืนโครงหน้ารายงาน
Puzzle: จัดส่วนหัว เมนู เนื้อหา และท้ายหน้า

ผลต่อเรื่อง: เปิดหน้ารายงานฉบับเต็ม

ด่าน 2 — เชื่อมหลักฐานต้นฉบับ
Puzzle: จับคู่แฟ้ม ภาพ และคำอธิบาย
โค้ด: ทบทวน a/href และ img/src/alt
ผลต่อเรื่อง: เปิดหลักฐานอ้างอิงที่สำเนารายงานขาดไป

ด่าน 3 — ต่อแผง CSS
Puzzle: เชื่อมไฟล์ HTML กับไฟล์ stylesheet
โค้ด: เติม link rel="stylesheet" และแก้ CSS declaration
ผลต่อเรื่อง: หน้าบันทึกกลับมาอ่านและใช้งานได้

ด่าน 4 — ระบุเป้าหมาย
Puzzle: จับคู่ selector กับองค์ประกอบในพรีวิว
โค้ด: ใช้ element selector, class และ id ขั้นพื้นฐาน
ผลต่อเรื่อง: แยกรายการจริงออกจากข้อความแทรกของ NULL

ด่าน 5 — คืนความชัดเจน
Puzzle: เลือกสีและขนาดข้อความที่อ่านได้
โค้ด: color, background-color, font-size และ line-height
ผลต่อเรื่อง: อ่านเวลา หมายเลขอุปกรณ์ และหมายเหตุได้ครบ
อย่าใช้สีเพียงอย่างเดียวบอกสถานะ

ด่าน 6 — ซ่อมกรอบข้อมูล
Puzzle: แยก content/padding/border/margin
โค้ด: แก้ระยะและใช้ box-sizing: border-box
ผลต่อเรื่อง: ข้อมูลที่เคยล้นกรอบกลับมาแสดงครบ

ด่าน 7 — จัดหน้าควบคุม
Puzzle: จัดกลุ่มการ์ดและช่องว่างตามภาพตัวอย่าง
โค้ด: display:flex, gap และ flex-wrap ขั้นพื้นฐาน
ผลต่อเรื่อง: ประกอบหน้ารวมหลักฐานและเปิดทางถึง BLACKBOX

6. ภารกิจที่ 8 — Boss Fight: NULL / Counterhack สามรอบ

ใช้รูปแบบที่ผู้ใช้เลือกแล้ว:
คินถูก NULL แฮ็ก → ผู้เล่นกู้โค้ด → ต่อวงจรส่งสัญญาณสวนกลับ
→ เห็นแพ็กเก็ตวิ่งจริง → คินโจมตี → NULL เสียระบบหนึ่งชั้น

คินและ NULL ขนาดปกติอยู่ในฉาก 2D ห้อง BLACKBOX
NULL ยึดอุปกรณ์สื่อสารคินจนคำสั่งของผู้เล่นส่งเข้าไปไม่ได้
ผู้เล่นกู้เทอร์มินัลและหมุนวงจรผ่าน GUI
ไม่เพิ่มระบบเดินหลบ พุ่งหลบ ทางโล่–สะพาน หรือร่างยักษ์จากแบบที่ยกเลิก

เล่นสามรอบตามลำดับ เป้าหมายกระชับประมาณ 3–5 นาทีตามเวลาคิด
เป็นเป้าหมายทดลองเล่น ไม่ใช่นาฬิกาแพ้ ไม่จับเวลาอ่านหรือเขียนโค้ด
ไม่ยืด animation หรือบังคับรอให้ครบความยาว

รอบ 1 — ตัดการควบคุม
NULL ล็อกช่องสื่อสารคินและเปลี่ยน href ไปแฟ้มปลอม
ให้โครง HTML สั้นพร้อมรายชื่อแฟ้มจำลองที่อ้างอิงได้
ผู้เล่นซ่อมลิงก์ให้เปิดต้นฉบับก่อนปลดล็อกแผงวงจร
แผงรอบนี้สอนต้นทาง ปลายทาง และการหมุนข้อต่อ ไม่มีตัวดัก
ส่งสำเร็จแล้วคินกระชากตัวหลุดล็อกและโจมตีเกราะชั้นแรก

รอบ 2 — วางตัวดัก
NULL แทรก CSS selector ให้เลือกคนละองค์ประกอบกับเป้าหมาย
ผู้เล่นตรวจ HTML และแก้ selector ตาม class/id ที่ให้จริง
พรีวิวแสดงว่าเลือกองค์ประกอบถูกหรือผิดอย่างไร
แผงวงจรมีตัวดักหนึ่งช่อง มีสัญลักษณ์และคำอธิบายชัด
ผู้เล่นหมุนทางอ้อมตัวดักไปถึง NULL
ส่งสำเร็จแล้วจอของ NULL ดับตามเส้นทางสัญญาณ เกราะแตก
คินสวนกลับด้วยท่าที่ต่างจากรอบแรก

รอบ 3 — ยึด BLACKBOX
NULL ปิดช่องส่งหลัก เหลือเส้นทางสำรองผ่านตัวขยายสัญญาณ
ผู้เล่นกู้หน้าควบคุมสั้นจากโครงที่ให้ ทบทวน HTML/CSS ที่เรียนแล้ว
ไม่ต้องพิมพ์ทั้งเว็บใหม่และไม่เพิ่มทักษะที่ยังไม่สอน
แผงวงจรต้องเชื่อมผ่านตัวขยายก่อนเข้าปลายทาง
ส่งสำเร็จแล้วคลื่นสุดท้ายตัดการยึดอุปกรณ์
คินเข้าถึงแท่นและถอด BLACKBOX พร้อมเก็บหลักฐานต้นฉบับ

มินิเกมต่อวงจร:
- กระดาน 3 แถว × 4 คอลัมน์ มีต้นทางคินและปลายทาง NULL
- ข้อต่อเป็นทางตรงและทางเลี้ยว หมุนครั้งละ 90 องศา
- ต้นทาง ปลายทาง ตัวดัก และตัวขยายเป็นจุดคงที่ที่มีป้ายกำกับ
- คลิกเลือกช่อง มีปุ่มหมุนและปุ่มส่งสัญญาณชัดเจน
  คีย์บอร์ดใช้ลูกศรเลือกช่อง Enter หมุน และ Tab ไปปุ่มส่งได้
  ไม่แย่ง Enter/Space จาก editor หรือปุ่ม UI อื่น
- มีตรวจเส้นทางก่อนส่ง การตรวจไม่ให้คะแนนหรือข้ามรอบ
- กดส่งแล้วแพ็กเก็ตวิ่งตามช่องที่เชื่อมต่อจริง ตรวจพอร์ตทั้งสองฝั่ง
  รับเส้นทางที่ถูกต้องทุกแบบ ไม่บังคับตรงภาพเฉลยเพียงรูปเดียว
- ทางขาด ออกขอบ เจอตัวดัก หรือวนไม่ถึงปลายทาง ให้หยุดตรงนั้น
  รอบสามต้องผ่านตัวขยายก่อนถึง NULL จึงสำเร็จ
- บอกจุดที่สัญญาณขาดพร้อมเหตุผล แล้วแก้เฉพาะวงจรต่อได้
  ไม่ล้างทิศที่หมุนไว้ ไม่บังคับทำโจทย์โค้ดที่ผ่านแล้วซ้ำ
- ทุกแผงต้องตรวจยืนยันว่ามีทางชนะ มีตัวอย่างสอนรอบแรก
  ไม่สุ่มเปลี่ยนช่องขณะที่ผู้เล่นวางแผน

การลองใหม่และความยุติธรรม:
โค้ดที่ NULL แทรกเป็นโจทย์ตั้งต้นก่อนเริ่มแต่ละรอบ
เทียบกับข้อมูลต้นฉบับที่เกมให้ได้ มีคำใบ้และเฉลยสีชมพู
ไม่สุ่มแก้ร่างที่กำลังพิมพ์ สลับปุ่มพิมพ์ หรือลบงานผู้เล่น
ตอบผิดให้เหตุผลและชี้บรรทัดเมื่อระบุตำแหน่งจริงได้
ส่งวงจรผิดให้ลองใหม่รอบนั้น เก็บ codePassed และคะแนนเดิมไว้
เกราะ NULL สามชั้นบอกความคืบหน้า รอบละหนึ่งชั้น
ไม่เพิ่มระบบหักเลือดผู้เล่นหรือจับเวลาจากแนวที่ยกเลิก

จังหวะภาพและเสียง:
ตอนโดนแฮ็ก สายม่วงจาก NULL ล็อกอุปกรณ์คิน คินมีท่าสะดุด/เกร็ง
แสงจอเปลี่ยนและการรบกวนอยู่ขอบจอ ไม่ทับข้อความหรือโค้ด
ส่งสำเร็จแล้วสายเปลี่ยนเป็นฟ้า แพ็กเก็ตวิ่งย้อนทาง คินโจมตีจริง
NULL มีท่ารับแรงกระแทก เกราะแตกและจอดับเป็นแนว
ใช้เฟรมท่าทางและชั้นเอฟเฟกต์ ไม่เลื่อนตัวละครทั้งใบแทนท่าโจมตี
มีเสียงสัญญาณ รีเลย์ impact และแท่นปลดล็อก ไม่มีเสียงพากย์
คงเพลง Hack เดิมผ่าน editor/วงจร/ท่าโจมตีโดยไม่เริ่มซ้ำ

หลังแต่ละรอบ แสงหรืออุปกรณ์ในห้องเปลี่ยนสภาพให้เห็นจริง
ปุ่มมี hover/focus/pressed ฉากมีแสงหรี่ เครื่องจักรและข้อมูลเคลื่อนไหว
Reduced motion ลดการสั่น/กระตุก/กล้อง แต่ยังอ่านเส้นทางและผลสำเร็จได้
เคารพ mute และระดับเสียงเดิม

สถานะรอบเป็น code → circuit → impact → next/completed
ส่งซ้ำระหว่างแพ็กเก็ตหรือท่าโจมตีต้องไม่ให้คะแนนซ้ำ
เปิดเมนูหรือซ่อนแท็บให้พักการเคลื่อนไหวและเสียงตามระบบเดิม
กลับมาแล้วไม่ข้ามรอบหรือยิงคำสั่งค้าง ท่าโจมตีสำเร็จจึงไปต่อ
บอสแต่ละรอบได้สิบคะแนน รวมสามสิบ

7. หน้าซ่อมและบทสนทนา

ต่อยอดหน้าพิมพ์ CodeMirror เดิมให้รองรับ HTML และ CSS:
เลขบรรทัด สี syntax ปุ่มแทรกแท็ก/คุณสมบัติ
Undo พรีวิว sandbox และ Ctrl+Enter

ตรวจโครงสร้างไม่มอบความคืบหน้า
ส่งคำสั่งซ่อมจึงตรวจและบันทึกผลผ่าน
ยอมรับคำตอบถูกที่เขียนต่างรูปแบบได้

มีคำใบ้และปุ่มเฉลยสีชมพูทุกโจทย์
ไม่หักคะแนนจากการลองใหม่หรือใช้ตัวช่วย
บันทึกการใช้ตัวช่วยแยกจากคะแนนเกม

บทสนทนาขณะเล่นอยู่ล่างจอและเบลอฉากด้านหลัง
Storyboard เหตุการณ์ไม่เบลอ
ภาษาไทยใช้ Chakra Petch ขนาดอ่านง่าย
ไม่มี glitch ผ่านข้อความสำคัญ

คินกวนเบา ๆ แต่ช่วยชี้ทาง:
“กรอบล้นอยู่ อย่าเพิ่งโทษจอ ดู padding ก่อน”
NULL ยั่วโดยอ้างถึงสิ่งที่ผู้เล่นเพิ่งพบ
ไม่พูดคำขู่ลอย ๆ ซ้ำทุกครั้ง

8. จบเกมและผลการเรียน

คะแนนตอนนี้:
เจ็ดภารกิจด่านละสิบคะแนน บอสสามสิบคะแนน

แสดงคะแนนเกมแยกจากความเข้าใจ:
ทำเอง / ใช้คำใบ้ / ดูเฉลย

ปิดท้ายด้วยโจทย์ประยุกต์หน้าแนะนำบริการซ่อมคอมพิวเตอร์
ให้ใช้ทักษะจากทั้งสามตอน มี header/nav/main/footer
ข้อความบริการ ลิงก์ ภาพพร้อม alt และ CSS พื้นฐาน

มีแบบวัดหลังเรียนและสะท้อนคิด:
- ส่วนใดของ HTML/CSS ที่เข้าใจมากขึ้น
- จุดไหนยังต้องฝึก
- จะนำไปใช้กับเว็บไซต์ของตัวเองอย่างไร

แสดงผลกู้ BLACKBOX และสถานะคดีอย่างชัดเจน
ไม่ถือว่าจบเกมเท่ากับทำข้อสอบได้ด้วยตนเองทั้งหมด

9. สิ่งส่งมอบและข้อจำกัด

ส่ง storyboard ฉากแยกชั้น ผัง collision ตำแหน่งเบาะแส
โมเดล CONTROL-03 ที่แก้ไขและส่งออก GLB ได้
ข้อมูลเจ็ดด่าน โจทย์บอส บทพูด และหน้าสรุปผล

ต่อยอด renderer ระบบเสียง คำสั่ง J/M/H และระบบเซฟเดิม
ปุ่มลัดต้องเคารพ editor หน้าต่างบทสนทนาและช่วงส่งสัญญาณ
เพิ่มสถานะตอนสุดท้ายโดยไม่ทำลายเซฟสองตอนแรก

ข้อกำหนดสำหรับการพัฒนาในอนาคต:
- เพิ่ม control เป็น chapter adapter จริงสำหรับภาคสนาม Circuit City
  งานซ่อม และจุดกลับ แยกตอนจาก street/device/boss ตามรูปแบบเดิม
  เปิด renderer ที่ใช้ครั้งละตัว
- control chapter module เป็นเจ้าของสองเบาะแส Puzzle งานตรวจโค้ด
  เจ็ดด่านและบอสสามรอบ map/camera/editor/DialogueSurface รับข้อมูล
  ผ่าน interface ร่วม กฎคดียังอยู่กับเจ้าของเดิม ไม่สร้าง generic mission engine
- ใช้ repair-session adapter รวม task/puzzle/check/submit/preview
  แทนเพิ่มเงื่อนไข if control กระจายทั่วหน้าซ่อม
- CodeMirror ปัจจุบันเน้น HTML ต้องเพิ่มโหมด CSS และ parser จริง
  ตรวจ selector/declaration ตามความหมาย รับรูปแบบที่ถูกต้องเทียบเท่ากัน
  ใช้ตำแหน่ง error จากต้นฉบับ ไม่เทียบสตริงเฉลยอย่างเดียว
- เพิ่ม control preview adapter ที่เก็บ class/id และ CSS ที่ใช้สอน
  แก้การกรองเดิมที่ลบ style/link/class ออกทั้งหมด ให้ stylesheet ภาพ
  และลิงก์เป็นแฟ้มจำลองที่เกมจัดให้เท่านั้น
  ปฏิเสธ script/event handler/URL ภายนอก/CSS import และการนำทางออก
  CSS ผู้เรียนมีผลเฉพาะ iframe ไม่รั่วมายัง HUD หรือหน้าเกม
  ไม่โหลด stylesheet อินเทอร์เน็ตเพื่อให้โจทย์ในเกมทำงาน
- Counterhack module รับคำสั่งหมุน ตรวจ และส่งวงจร แยกผลตรวจทาง
  จาก animation; codePassed อยู่ต่อเมื่อส่งวงจรผิด
  ไม่เก็บร่างโค้ดหรือเฟรม animation ลง cloud
- เซฟ control แยกตาม owner/reset generation เช่นสองตอนแรก
  Reset/สลับบัญชียกเลิก callback เสียง และผลตอบกลับของเจ้าของเดิม
- เพิ่ม milestone recover-blackbox ที่ต้องมี recover-relay ก่อน
  read-control เดิมเป็นประวัติข่าวกรอง ไม่ใช่ผลผ่านตอนสุดท้าย
  เปลี่ยนรุ่นสัญญาเซฟ client/server พร้อมกัน อ่านรุ่น 1–2 ได้
  ไม่ลบหลักฐานเดิม รักษา revision/reset generation และ JSON storage เดิม
- เก็บคะแนนบอสรายรอบ ไม่ให้รับซ้ำจาก replay ความคืบหน้าคดีออนไลน์
  เป็น milestone รายละเอียดการฝึกยัง local ตามขอบเขตเดิม
  อย่าอ้างว่า cloud เก็บทุกขั้นหรือทุกบรรทัดโค้ดแล้ว
- แบบวัดหลังเรียน โจทย์เว็บบริการซ่อมและสะท้อนคิดเป็นงานใหม่
  ต้องออกแบบและตรวจจริง ไม่ถือว่าเป็นหน้าที่มีพร้อมอยู่แล้ว

ตรวจเดินชน การหยุดใต้หน้าต่าง ด่านล็อก คำตอบถูก/ผิดและรูปแบบเทียบเท่า
ตรวจเจ็ด Puzzle/งานโค้ด และ Counterhack สามรอบ
ตรวจวงจรขาด ออกขอบ วน ตัวดัก ไม่ผ่านตัวขยาย และทางเลือกที่ถูกต้อง
ตรวจส่งซ้ำ ตรวจอย่างเดียวไม่ให้คะแนน ส่งผิดไม่ล้าง codePassed
ตรวจพัก/กลับเกม ข้ามบท เซฟเก่า สลับบัญชีและ Reset
ตรวจ CSS ไม่กระทบหน้าเกม ไม่มี script/URL ภายนอกหลุดเข้า preview
ตรวจท่าโจมตีและเกราะสัมพันธ์กับแพ็กเก็ต เสียงไม่ซ้อน mute/reduced motion
ตรวจสองตอนเดิมไม่ถดถอย คอมพิวเตอร์ 1280×720, 1440×900 และ 1920×1080
รวมเต็มจอ ไม่ทดสอบมือถือ พร้อมภาพ/คลิปและ production build

เริ่มจากร่างภาพรวมฉากและ storyboard ก่อนลงระบบเต็ม
Prompt นี้เป็นข้อกำหนดสำหรับพัฒนาตอนสามในอนาคต
รอบส่งมอบเอกสารนี้ยังไม่สร้างตอนสามหรือแก้ runtime
การเผยแพร่เกมสองตอนปัจจุบันและแก้ Login เป็นงานแยกที่ผู้ใช้สั่งแล้ว
อย่าอ้างว่า deployment รอบนั้นมีตอนสามจนกว่าจะพัฒนาและตรวจรับจริง
